# 農場圖片顯示：移植與拼接說明

目標：把目前**只用文字顯示**的農場面板加上圖片並上傳到 Discord：農田圖（4～16 格）、建築畫面（畜舍、3 台加工機器、動物），以及商店頁面。
搬到其他電腦時，帶走 **整個 `farm/` 素材資料夾（含本文件與 `manifest.json`）**，再照第 1～3 節修改目標專案即可。

本文件以原專案 farmgm 的結構說明（`game/balance.py`、`services/game_service.py`、`discord_bot/panels.py`…）。目標專案的邏輯有改過，請找**功能相同的函式**套用，不要照抄行號。

---

## 0. 移植清單

| 項目 | 做法 |
|---|---|
| 素材資料夾 | 整個 `farm/` 複製到目標專案，例如 `app/discord_bot/assets/farm/` |
| 執行時需要 | `manifest.json` 與所有子資料夾（`field/`、`yard/`、`scenes/`、`crops/`、`badges/`…，約 22 MB） |
| 可以不帶 | `farmimg2.png`、`farm.png`、`gabe.png`、`background.png`、`shop.png`（原圖，約 12 MB，只在重新產生素材時使用；處理好的成品在 `field/`、`yard/`、`scenes/`） |
| Python 套件 | `Pillow>=11,<13`，加進 `requirements.txt`，安裝文件也要同步更新 |
| 不需要 | 字型、資料庫 Migration（規則上限只在服務層檢查，見 1.6） |

修改步驟總覽：
1. 遊戲規則：農田最多 16 格（第 1 節）
2. 新增圖片模組 `farm_image.py`（第 2 節）
3. 面板接上圖片（第 3 節）
4. 補上測試（第 9 節）

---

## 1. 遊戲規則修改：農田最多 16 格

圖片是 4×4 的田，所以遊戲必須限制最多 16 格。原專案的擴建**沒有上限**（每次 +2 格），管理員則可以加到 100 格。

### 1.1 常數（`game/balance.py`）
```python
INITIAL_PLOTS = 4
UPGRADE_PLOTS_ADDED = 2
MAX_PLOTS = 16          # 新增：每座農場最多土地數（農田圖片為 4×4）
ADMIN_MAX_PLOTS = MAX_PLOTS   # 原本是 100，改成跟著 MAX_PLOTS
```

### 1.2 擴建土地（`GameService.upgrade_farm`）
在**扣金幣之前**檢查；這個錯誤要是 `GameError` 的子類別，面板才會把訊息直接顯示給玩家：
```python
farm = self._locked_farm(session, player_id)
total = farms_repo.count_plots(session, farm.id)
if total + balance.UPGRADE_PLOTS_ADDED > balance.MAX_PLOTS:
    raise ValidationError(f"農田已達上限 {balance.MAX_PLOTS} 格，無法再擴建。")
cost = balance.UPGRADE_COST
...（原本的扣款、加格子、升級）
```
- 4 格起算、每次 +2，擴建 6 次就會到 16 格。
- **副作用：等級。** 原專案每次擴建等級 +1，等級會影響品質加成（`level_bonus_bp`，每級 +0.5%，最多 +5%）。有上限後，靠擴建最多只能到 7 級，品質加成最多 +3%。如果要保留到 +5%，請另外提供升級管道，或調整 `level_bonus_bp`。
- 如果目標專案的 `UPGRADE_PLOTS_ADDED` 不是 2，或初始格數不是 4，要確認 `INITIAL_PLOTS + k × UPGRADE_PLOTS_ADDED` 剛好可以到 16。不能剛好到時，判斷式會在接近 16 時擋下擴建；如果希望能補到剛好 16 格，改成「本次只加 `MAX_PLOTS − total` 格」。

### 1.3 管理員新增土地（`AdminService.add_plots`、`api/admin.py`）
- `_int(count, ..., 1, balance.ADMIN_MAX_PLOTS)` 和 `total + count > ADMIN_MAX_PLOTS` 的檢查保留，上限自動變成 16。
- `PlotsBody.count: Field(ge=1, le=balance.ADMIN_MAX_PLOTS)` 不用改。
- 如果管理網站前端有寫死上限（原專案沒有），改成 16。

### 1.4 面板的擴建按鈕（`panels.py::_build_plots`）
已達上限時停用按鈕，避免玩家按了才看到錯誤：
```python
full = len(s.plots) >= balance.MAX_PLOTS
self.button("已達上限" if full else ("確認擴建" if confirming else f"擴建（{balance.UPGRADE_COST} 金）"),
            upgrade, emoji="⬆️", row=1, disabled=full, style=...)
```

### 1.5 其他顯示文字
- CLI 說明（`cli/commands.py` 的 `upgrade` 說明、商店頁的「擴建土地」）加上「最多 16 格」。
- Discord 文字指令 `/upgrade` 的描述、`/help`、介紹網站的手冊（`/api/guide` 若有輸出擴建資訊，可加 `max_plots`）。

### 1.6 既有資料
- 先檢查有沒有超過 16 格的農場：
  ```sql
  SELECT farm_id, count(*) FROM farm_plots GROUP BY farm_id HAVING count(*) > 16;
  ```
- **不要自動刪除土地**（上面可能有作物）。建議保留，圖片只畫前 16 格、文字清單照常列出全部；或由管理員和玩家溝通後手動刪除。
- 不建議加資料庫 CHECK 或觸發器：既有資料可能違反，而且管理員刪除再新增時，計數會比較複雜。上限只在服務層檢查就夠了。

## 2. 新增圖片模組 `farm_image.py`

放在目標專案的 Discord Bot 資料夾（例如 `app/discord_bot/farm_image.py`）。只依賴 Pillow 與素材資料夾，**下面的程式已在原專案實際執行測試過**（農田：各種格數、預先產生的圖命中、補標記、未知作物；建築畫面：空場地、只有建築、全滿＋加工＋動物、動物超過畜舍容量、未知動物）。

包含三個對外函式：`farm_png_from_status(status)` 農田圖、`yard_png(workshop, animals)` 建築畫面、`shop_png()` 商店頁面。

```python
"""農場圖片：依農田狀態拼出 4～16 格的農田 PNG（素材與規則見 assets/farm/拼接說明.md）。"""
import io
import json
from pathlib import Path

from PIL import Image

ASSETS = Path(__file__).resolve().parent / "assets" / "farm"   # ← 素材資料夾位置

_manifest = json.loads((ASSETS / "manifest.json").read_text(encoding="utf-8"))
_field = _manifest["field"]
_cache: dict[str, Image.Image] = {}
STATE_BADGE = {"seeds": "need_water", "sprout": "timer", "young": "timer", "unripe": "timer", "ready": "ready"}


def img(rel: str) -> Image.Image:
    if rel not in _cache:                     # 素材只讀一次，之後重複使用
        _cache[rel] = Image.open(ASSETS / rel).convert("RGBA")
    return _cache[rel]


def plots_from_status(status) -> list[dict]:
    """把服務層的 FarmStatus（plots: list[PlotInfo]、now）轉成拼圖用的資料，依 plot_number 排序。"""
    out = []
    for p in sorted(status.plots, key=lambda p: p.plot_number):
        progress = 0.0
        if p.watered_at and p.ready_at and p.ready_at > p.watered_at:
            progress = (status.now - p.watered_at) / (p.ready_at - p.watered_at)
        out.append({"crop": p.crop_code, "state": str(p.state), "progress": min(1.0, max(0.0, progress)),
                    "quality": p.quality, "mutation": p.mutation})
    return out


def stage_of(plot: dict) -> str:
    """回傳畫面階段：empty／seeds／sprout／young／unripe／ready／withered（見第 4 節）。"""
    state = plot["state"]
    if state == "waiting_water":
        return "seeds"
    if state == "growing":
        th = _manifest["layering"]["growing_thresholds"]          # sprout 0.4、young 0.75
        p = plot.get("progress", 0)
        return "sprout" if p < th["sprout"] else "young" if p < th["young"] else "unripe"
    return state


def plant_layer(plot: dict, stage: str) -> str | None:
    crops = _manifest["crops"]
    crop = crops.get(plot.get("crop") or "", crops["_generic"])   # 未知作物 → _generic
    if stage == "empty":
        return None
    if stage in ("seeds", "sprout", "young"):
        return crops["_generic"][stage]
    if stage == "ready" and plot.get("mutation") == "variant" and "variant" in crop:
        return crop["variant"]["ready"]
    return crop[stage]


def attr_badges(plot: dict) -> list[str]:
    """品質與突變標記（只有可收成時才畫）。"""
    badges = _manifest["badges"]
    out = []
    if plot.get("quality") in badges["quality"]:
        out.append(badges["quality"][plot["quality"]])
    if plot.get("mutation") in badges["mutation"]:
        out.append(badges["mutation"][plot["mutation"]])
    return out


def draw_attr_badges(canvas: Image.Image, rect: list[int], plot: dict) -> None:
    for i, rel in enumerate(attr_badges(plot)):
        canvas.alpha_composite(img(rel), (rect[0] + 2 + i * 22, rect[1] + 2))


def draw_plot(canvas: Image.Image, rect: list[int], plot: dict) -> None:
    x0, y0, x1, y1 = rect
    w, h = x1 - x0, y1 - y0
    stage = stage_of(plot)
    if plot["state"] in ("growing", "ready"):                      # 1 濕土
        canvas.alpha_composite(img(_field["wet_overlay"]).resize((w, h)), (x0, y0))
    layer = plant_layer(plot, stage)                               # 2 植物
    if layer:
        sprite = img(layer)
        canvas.alpha_composite(sprite, (x0 + (w - sprite.width) // 2, y1 - sprite.height - 2))
    if stage in STATE_BADGE:                                       # 3 右上：狀態
        canvas.alpha_composite(img(_manifest["badges"][STATE_BADGE[stage]]), (x1 - 24 - 2, y0 + 2))
    if stage == "ready":                                           # 4 左上：品質、突變
        draw_attr_badges(canvas, rect, plot)


def preset_for(plots: list[dict]) -> tuple[str, bool] | None:
    """全部種滿同一作物、同一階段時，回傳 (預先產生的圖, 是否還要補品質／突變標記)。"""
    presets = _field["presets"].get(str(len(plots)))
    if presets is None:
        return None
    stages = {stage_of(p) for p in plots}
    if len(stages) != 1:
        return None
    stage = stages.pop()
    if stage == "empty":
        return presets["empty"], False
    crops = {p.get("crop") for p in plots}
    if len(crops) != 1 or (crop := crops.pop()) not in presets:
        return None
    if stage == "ready" and any(p.get("mutation") == "variant" for p in plots):
        return None                                               # 變種外觀不同，要即時拼
    return presets[crop][stage], stage == "ready" and any(attr_badges(p) for p in plots)


def encode(image: Image.Image) -> bytes:
    buf = io.BytesIO()                        # 256 色 PNG：約為全彩的 1/5，編碼也快很多
    image.quantize(256, method=Image.Quantize.FASTOCTREE, dither=Image.Dither.NONE).save(buf, "PNG")
    return buf.getvalue()


def farm_png(plots: list[dict]) -> bytes:
    """plots 依 plot_number 排序（plots_from_status 的結果）。回傳要上傳的 PNG 內容。"""
    plots = plots[:_field["slots"]]                               # 最多畫 16 格
    hit = preset_for(plots)
    if hit and not hit[1]:
        return (ASSETS / hit[0]).read_bytes()                     # 直接上傳預先產生的圖
    if hit:                                                       # 預先產生的圖 + 補標記
        canvas = img(hit[0]).copy()
        for k, plot in enumerate(plots):
            draw_attr_badges(canvas, _field["cells"][k]["rect"], plot)
        return encode(canvas)
    n = min(max(len(plots), _field["min_plots"]), _field["slots"])  # 底圖 4～16
    canvas = img(_field["bases"][str(n)]).copy()
    for k, plot in enumerate(plots):
        draw_plot(canvas, _field["cells"][k]["rect"], plot)
    return encode(canvas)


def farm_png_from_status(status) -> bytes:
    return farm_png(plots_from_status(status))


# ---------- 建築畫面（第 6 節） ----------
def yard_key(counts: dict) -> str:
    """建築數量 → 底圖 key，例如 {"barn": 2, "mill": 1, "bakery": 0, "jam_workshop": 1} → "2-101"。"""
    yard = _manifest["yard"]
    barns = min(counts.get("barn", 0), len(yard["barn_slots"]))
    return f"{barns}-" + "".join("1" if counts.get(code, 0) else "0" for code in yard["machine_order"])


def draw_bubble(canvas: Image.Image, pos: list[int], icon_rel: str) -> None:
    """32×32 對話泡泡＋中央 20×20 圖示。"""
    bubble = img(_manifest["badges"]["bubble"]).copy()
    icon = img(icon_rel).resize((20, 20), Image.LANCZOS)
    bubble.alpha_composite(icon, (6, 5))
    canvas.alpha_composite(bubble, tuple(pos))


def yard_png(workshop: dict, animals: list[dict]) -> bytes:
    """workshop = workshop_status()；animals = list_animals()。回傳建築畫面 PNG。"""
    yard, badges = _manifest["yard"], _manifest["badges"]
    base_rel = yard["bases"][yard_key(workshop["counts"])]
    overlays = False
    canvas = None

    def target() -> Image.Image:
        nonlocal canvas, overlays
        if canvas is None:
            canvas = img(base_rel).copy()
        overlays = True
        return canvas

    # 加工機器：加工中 → 沙漏；可領取 → 成品圖示
    for code, info in yard["machines"].items():
        order = workshop["busy"].get(code)
        if not workshop["counts"].get(code) or not order:
            continue
        if order["state"] == "in_progress":
            draw_bubble(target(), info["bubble"], badges["timer"])
        elif order["state"] == "ready":
            draw_bubble(target(), info["bubble"], _manifest["goods"].get(order["output_code"], badges["ready"]))

    # 動物：依 animal_no 排序，第 i 隻放第 i // 4 座畜舍那一欄的第 i % 4 個位置
    barns = min(workshop["counts"].get("barn", 0), len(yard["barn_slots"]))
    size = yard["animal_size"]
    for i, a in enumerate(sorted(animals, key=lambda a: a["animal_no"])[:barns * 4]):
        cx, by = yard["animal_spots"][i // 4][i % 4]
        sprite = img(_manifest["animals"].get(a["code"], _manifest["animals"]["_generic"])).resize(
            (size, size), Image.LANCZOS)
        target().alpha_composite(sprite, (cx - size // 2, by - size))
        if a["state"] == "hungry":
            draw_bubble(canvas, [cx - 16, by - size - 26], badges["hungry"])
        elif a["state"] == "ready":
            draw_bubble(canvas, [cx - 16, by - size - 26],
                        _manifest["products"].get(a.get("product_code"), badges["ready"]))

    if not overlays:
        return (ASSETS / base_rel).read_bytes()               # 沒有動物、機器都閒置：直接上傳底圖
    return encode(canvas)


def shop_png() -> bytes:
    """商店頁面是固定圖片，直接上傳檔案（第 7 節）。"""
    return (ASSETS / _manifest["scenes"]["shop"]).read_bytes()
```

實測速度：預先產生的圖或底圖命中時只讀檔（< 1 ms）；即時拼 16 格農田加編碼約 10～25 ms；建築畫面含 12 隻動物與泡泡約 20 ms。

## 3. 面板接上圖片（`discord_bot/panels.py`、`commands.py`）

原面板的流程：`render()` 在執行緒中呼叫 `_load_<頁面>()`，再用 `_build_<頁面>()` 建 Embed；`refresh()` 用 `edit_original_response(embed=..., view=...)` 更新訊息。照下面加上圖片：

### 3.1 `FarmPanel` 加附件欄位，每次重建時清空
```python
import io
from app.discord_bot import farm_image

FARM_IMAGE = "farm.png"

class FarmPanel(discord.ui.View):
    def __init__(...):
        ...
        self.files: list[discord.File] = []      # 本次畫面要附上的圖片

    async def render(self, notice=None):
        self.clear_items()
        self.files = []                          # 換頁時圖片也要清掉
        ...（原本的內容）

    def attach_farm_image(self, embed: discord.Embed, png: bytes | None) -> None:
        if png:                                  # discord.File 只能送出一次，每次都要建新的
            self.files = [discord.File(io.BytesIO(png), filename=FARM_IMAGE)]
            embed.set_image(url=f"attachment://{FARM_IMAGE}")
```

### 3.2 讀資料時一起拼圖（在執行緒中，不會卡住事件迴圈）
```python
def _farm_image(self, status) -> bytes | None:
    try:
        return farm_image.farm_png_from_status(status)
    except Exception:                            # 素材缺漏不能讓整個面板壞掉，退回純文字
        logger.exception("農田圖片產生失敗（玩家 #%s）", self.player_id)
        return None

def _load_main(self):
    status = svc.get_farm_status(pid)
    return {"status": status, ..., "image": self._farm_image(status)}

def _build_main(self, d):
    e = ...（原本的 Embed）
    self.attach_farm_image(e, d["image"])
    return e
```
「🌱 農田」頁（`_load_plots`／`_build_plots`）也用同樣的方式加上。其他頁面不呼叫 `attach_farm_image`，圖片就會自動消失。

### 3.3 送出與更新訊息時帶上附件
```python
# refresh()：attachments 傳 [] 會移除舊圖，傳新檔案會取代
await interaction.edit_original_response(embed=embed, view=self, attachments=self.files)

# show_error()：錯誤畫面不顯示圖片
await interaction.edit_original_response(embed=embed, view=self, attachments=[])

# commands.py 第一次開啟面板
panel.message = await interaction.followup.send(
    embed=embed, view=panel, ephemeral=True, wait=True, **({"files": panel.files} if panel.files else {}))
```

### 3.4 「分享到頻道」（`_share`）
在執行緒中同時取得狀態與圖片，送出時附上：
```python
status = await self.run(self.svc.get_farm_status, self.player_id)
png = await self.run(self._farm_image, status)
e = discord.Embed(...)
kwargs = {}
if png:
    e.set_image(url=f"attachment://{FARM_IMAGE}")
    kwargs["file"] = discord.File(io.BytesIO(png), filename=FARM_IMAGE)
await interaction.followup.send(embed=e, allowed_mentions=discord.AllowedMentions.none(), **kwargs)
```

### 3.5 建築畫面與商店頁面
```python
def _yard_image(self, workshop, animals) -> bytes | None:
    try:
        return farm_image.yard_png(workshop, animals)
    except Exception:
        logger.exception("建築畫面產生失敗（玩家 #%s）", self.player_id)
        return None

# 「🐔 動物」頁：原本就有 animals 與 workshop
def _load_animals(self):
    d = {...原本的內容...}
    d["image"] = self._yard_image(d["workshop"], d["animals"])
    return d

# 「🏭 加工」「🏗️ 建造設施」頁：原本沒有讀動物，補上 list_animals
def _load_craft(self):
    d = {...原本的內容...}
    d["image"] = self._yard_image(d["workshop"], self.svc.list_animals(self.player_id))
    return d
```
在 `_build_animals`／`_build_craft`／`_build_build` 結尾呼叫 `self.attach_farm_image(e, d["image"])`（同一個函式，檔名都用 `farm.png` 即可）。

商店頁（`_build_shop`）用固定圖片。圖片不需要讀資料庫，可以直接在 build 裡讀檔：
```python
self.attach_farm_image(e, farm_image.shop_png())
```

### 3.6 其他可以加圖片的地方（選用）
- 偷菜頁查看別人的農田：一樣用 `farm_png_from_status(target_status)`。
- 收成、澆水後的結果：`act()` 成功後會 `refresh()`，已經會顯示新圖，不需要另外處理。

### 3.7 注意
- Embed 的文字清單照常保留：品質、突變、化肥、成熟時間還是靠文字顯示；圖片只負責看起來直觀。
- 每次換頁或操作都會重新上傳一張圖：農田圖約 90～130 KB，建築畫面與商店約 140～230 KB。私密面板只有本人看得到，流量不大。
- `discord.File` 送出後就不能再用，所以每次 `render()` 都要建新的（3.1 已處理）。

## 4. 拼接規則（`farm_image.py` 已實作，換素材或改邏輯時參考）

### 4.1 土地狀態（與遊戲 `rules.plot_state` 相同）
| 條件（`farm_plots` 欄位） | 狀態 |
|---|---|
| `crop_type_id` 為空 | `empty` 空地 |
| 有作物、`watered_at` 或 `ready_at` 為空 | `waiting_water` 等待澆水 |
| `now < ready_at` | `growing` 生長中 |
| `now ≥ ready_at + WITHER_SECONDS`（30 分鐘） | `withered` 已乾枯 |
| 其他 | `ready` 可收成 |

生長進度：`progress = (now − watered_at) / (ready_at − watered_at)`（0～1）。目標專案若改過狀態判斷，`plots_from_status` 的 `state` 直接用服務層算好的結果即可，不要自己重算。

## 5. 預先產生的常用畫面（`field/presets/`）

「一鍵種滿」「全部澆水」之後，整片田會是同一種作物、同一階段，這是最常出現的畫面。玩家擴建只會出現 **4、6、8、10、12、14、16** 格，這幾種都已預先產生，命中時直接上傳檔案。

| 檔名（NN = 04、06…16） | 畫面 | manifest |
|---|---|---|
| `field/base_NN.png` | NN 格全空 | `field.presets.<格數>.empty` |
| `presets/NN_seeds.png` | 全部剛播種、等待澆水（作物共用） | `field.presets.<格數>.<作物>.seeds` |
| `presets/NN_sprout.png` | 全部嫩芽（作物共用） | `….<作物>.sprout` |
| `presets/NN_young.png` | 全部幼苗（作物共用） | `….<作物>.young` |
| `presets/NN_<作物>_unripe.png` | 全部快成熟 | `….<作物>.unripe` |
| `presets/NN_<作物>_ready.png` | 全部可收成 | `….<作物>.ready` |
| `presets/NN_<作物>_withered.png` | 全部乾枯 | `….<作物>.withered` |

`<作物>`：`carrot` 胡蘿蔔、`strawberry` 草莓、`tomato` 番茄、`wheat` 小麥。每種格數 15 張，共 105 張（約 12 MB）。manifest 的 `<格數>` 是不補零的字串，例如 `"4"`、`"16"`。

命中條件（`preset_for`）：格數有對應的預先產生圖、所有格子同階段、同作物（4 種之一）。可收成時不能有珍稀變種；有品質或突變時，拿預先產生的圖補貼標記即可。其他情況（混種、階段不一、奇數格）即時拼圖，也只要 20 ms 左右。

### 6.3 規則
- **畜舍順序**：遊戲的 `farm_buildings.slot` 就是同種建築的購買序號。畫面只看「有幾座」，第 1 座畫在位置 1，以此類推。管理員刪除後編號不連續也不影響。超過 3 座只畫 3 座。
- **動物**：遊戲中動物沒有指定畜舍（容量 = 畜舍數 × 4）。依 `animal_no` 排序後，第 i 隻放第 `i // 4` 座畜舍那一欄的第 `i % 4` 個位置，超過容量的不畫。
  - 圖片用 `animals/<代碼>.png` 縮成 48×48，未知動物用 `_generic`。
  - 待餵食在頭上畫泡泡＋`badges/hungry`；可收集畫泡泡＋`products/<產品代碼>`，找不到產品圖時用 `badges/ready`；生產中不畫泡泡，避免畫面太亂。
  - 泡泡位置：`(cx − 16, by − 48 − 26)`。
- **加工機器**（`workshop_status()["busy"][代碼]`）：`in_progress` 畫泡泡＋`badges/timer`；`ready` 畫泡泡＋`goods/<output_code>`；閒置不畫。
- 泡泡底圖是 `badges/bubble.png`（32×32），圖示縮成 20×20 貼在 (6, 5)。
- 遊戲新增其他建築種類時，需要另外決定位置並重新產生底圖（原專案 `scripts/build_farm_assets.py` 的 `YARD_*` 常數）。
